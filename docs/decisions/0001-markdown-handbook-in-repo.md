# 0001 設計文件改用 repo 內的 Markdown

> 狀態：已決定
> 日期：2026-10-11

## 背景
設計文件原本寫在 Notion handbook，但在 Notion 裡寫技術設計不直觀；
程式在 GitHub、設計在 Notion，兩邊常常對不起來，也看不出設計改過什麼。

## 考慮過的選項
1. **繼續用 Notion**：排版漂亮、方便非技術人員閱讀；但沒有版本紀錄可對照程式碼，AI 協作時也要另外複製貼上。
2. **repo 內的 Markdown（`/docs`）**：跟程式一起 commit，有完整版本紀錄；GitHub 直接顯示，Mermaid 流程圖會畫成圖；AI 工具可以直接讀寫。缺點是排版較陽春、非技術人員要到 GitHub 看。
3. **兩邊都寫**：容易不同步，不考慮。

## 決定
選 2。設計文件以 `/docs` 為準。
Notion 只保留「給行政老師看的操作說明」這類非技術內容（可之後再決定是否也搬過來）。

## 影響
- Notion 上既有的設計文件要逐步搬到 `/docs`，搬完標註「已搬到 GitHub」。
- repo 是公開的，所以文件裡不能放個資、金鑰、財務數字。
